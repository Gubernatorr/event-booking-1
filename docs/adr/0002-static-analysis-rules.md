# ADR 0002: Правила статичного аналізу

**Статус:** прийнято · **Дата:** 2026-11-05

## Контекст
Стиль коду і типові помилки перевірялися лише на код-рев'ю, тож щось пропускали.
Готовий google_checks.xml не беремо: він вимагає відступ у 2 пробіли і забороняє
табуляції, тож дав би сотні попереджень. Пишемо власний набір правил.

## Рішення

### Інструменти
| Інструмент | Що аналізує | Фаза Maven | Що ловить |
|---|---|---|---|
| Checkstyle | вихідний код (.java) | validate | стиль, іменування, імпорти, складність |
| SpotBugs | скомпільований байткод | verify | ймовірні баги: null, equals/hashCode, витік стану |
| SonarQube for IDE | код у редакторі | — (IntelliJ) | підказки під час написання коду |

### Правила
| Правило | Рішення | Чому |
|---|---|---|
| FileTabCharacter | вимкнено | у проєкті відступи табуляцією |
| tabWidth | 4 | щоб LineLength правильно рахував рядки з табуляціями |
| LineLength | змінено: max 120 | 80 замало для сучасних моніторів; package та import ігноруються |
| CyclomaticComplexity | max 10 | складніші методи важко покрити тестами |
| MethodLength | max 50 | довгий метод робить забагато |
| ParameterNumber | max 6, лише методи | конструктори Spring-бінів можуть мати більше залежностей |
| NestedIfDepth | max 2 | глибока вкладеність погано читається |
| ReturnCount | max 3 (void: 2) | багато return ускладнює розуміння логіки |
| HideUtilityClassConstructor | виняток для *Application.java | Spring сам створює екземпляр головного класу, private-конструктор зламає запуск |
| MethodLength, ReturnCount | виняток для src/test | тестові сценарії бувають довгими |

## Наслідки
- Збірка падає на будь-якому порушенні, тож проблеми не накопичуються.
- Новий виняток додаємо лише так: коментар у suppressions.xml або exclude.xml плюс рядок у таблиці вище з причиною.
- Глобально вимикаємо лише системний шум, поодинокі випадки — точково, справжні баги виправляємо в коді.
